## Follow-up the same day: the mirror hitching (the old performance HOLD) — root cause and fix

Symptom: 30-85 ms frames every ~100 ms whenever the live mirrors were on. Not the cost of the extra renders. Two causes, both in how three.js picks a shader per material:
1. The mirror pass ADDED a clipping plane to every material and removed it after. Plane count is part of the program key, so ~200 programs were re-resolved on entering and leaving each pass; the garbage from that produced GC pauses. Fix: one permanent plane per material, parked where it clips nothing, moved onto the glass only during a pass. Count never changes. (Experiment that proved it: switching off -> 26-81 spikes per 9 s became 6-13.)
2. Reflections were drawn from INSIDE the main render (`onBeforeRender`), i.e. at a deeper render-call depth with its own lights-state version, so every lit material flipped program again. Fix: `VehicleMirrors.render()` draws them as a top-level step before the frame (own frustum test); `onBeforeRender` remains only as a fallback for callers that never call `render()`.
Also: in chase view the two faces take turns (one pass per frame); cockpit refreshes every frame.
Result, harbor near view, 9 s, uncapped 1440p: 26-81 spikes (worst 57-85 ms) -> 1-7 (worst 31-36 ms); avg 7.3-12.6 -> 6.6-6.8 ms. Express: 0-2 spikes, 4.5-4.7 ms. Far view unchanged at 5.0 ms, so the permanent plane costs nothing. Still true on the direct path (reduced motion, low quality, showroom): main view is tone-mapped to the screen while mirrors render linear to a target, so that program flip remains there.
Checks: 317/317 tests (real-GPU mirror test passes in standard, reversed and log depth), build OK, cockpit/near/far/showroom smoke clean.
