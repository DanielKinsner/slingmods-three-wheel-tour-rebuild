# Phase 2A — post pipeline, quality presets, dynamic resolution, bloom (2026-09-21)

Decisions from the owner ("go" on the Phase 2 spec): three.js-native passes (no new dependency); After Rain visual only; Dusk/After Rain become the default look on Express and Harbor (slice 2B); 2K skies everywhere. Slice order: 2A pipeline -> 2B time of day -> 2C wet road -> 2D water -> 2E car-touches-world -> 2F grounding -> 2G ridge forest -> 2H texture pass.

1. `src/presentation/render-pipeline.ts`: scene -> one MSAA half-float HDR target -> bloom mip chain (soft-knee prefilter, down, tent up) -> ONE composite pass (bloom + Phase 1 edge blur/vignette + the same tone mapping and output colour as before). Drive scene and showroom both render through it; the single-purpose `speed-post.ts` is gone. If the GPU cannot give the HDR target it falls back to direct drawing by itself.
2. `graphics-settings.ts`: Low / Medium / High / Ultra (MSAA 0/2/4/4, bloom levels 0/4/5/6, pixel-ratio cap 1/1/1.5/2). Remembered under its OWN key `slingmods-graphics-v1`, never in the game save; `?quality=` forces one (old `standard` = High). In-drive selector `#game-graphics` shows only while the race menu is open, applies live; shadow budget (Low vs the rest) updates next drive. Not reachable by gamepad yet (Phase 3 menus).
3. Dynamic resolution never reallocates: the scene draws into the lower-left `scale` of a full-size target and readers scale UVs. Floor 60%, 5% steps, learns the display refresh, and after a failed climb under vsync holds that ceiling for a minute instead of bouncing. On for Low/Medium/High, off for Ultra.
4. Bloom: day threshold 1.35 (clouds, paint, white lines do NOT glow), night threshold 0.8 (headlights, DRLs, tail lamps do). Reduced motion now keeps every LOOK and removes only motion (blur strength 0, camera untouched).
5. Measured (uncapped 2560x1440, RTX 4080, near view, full throttle, 2 rounds), avg / worst-1% ms. Express: Low 5.1-5.4 / 10-15, Medium 5.3 / 13-15, High 5.4-5.5 / 14-16, Ultra 5.2-5.5 / 13-15. Harbor: Low 7.5-7.7 / 19-21, Medium 7.6-8.2 / 22-23, High 7.5-7.6 / 16-17.5, Ultra 7.2-7.3 / 19-27. Budget (High <= 10 avg, <= 16.6 worst-1%) met on express; harbor worst-1% is at the line. Two findings: drawing DIRECT was the slowest option (7.0 ms, 31 ms worst-1%: mirror passes flip every material between screen and target shader variants), so Low uses the pipeline too; and harbor is CPU/draw-call bound (Ultra at 100% scale costs the same as High at 85%). In the uncapped benchmark dynamic resolution chases a 144 Hz target, which is why High shows 85-95% scale there; on a vsynced 60 Hz display it stays at 100%.
Checks: typecheck clean, 323/323 tests (4 new in tests/phase2-pipeline.test.ts), production build OK, hosted package rebuilt and both flat routes reach the drive with 0 failed requests. No new assets, no save/physics/record change.
